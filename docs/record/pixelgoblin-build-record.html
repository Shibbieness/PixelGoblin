PixelGoblin Build Record

Last session was the design. This session built it. PixelGoblin now exists as a working, self-checking prototype. It has a stdlib-only Python engine, a command line, a browser workbench whose JavaScript core produces the same pixels as Python, and a Vanilla Core flavor. Building it also turned up a real bug in Vanilla Core, which is fixed here as a patch.

Every count on this page was computed by running the build when this page was made. None were typed in.

The name

PixelGoblin fits, and I'd keep it. Book of Cities goblins are improvised-into-comfort: they take scraps and make them livable. That is exactly what the tool does to an image. It scavenges it, then remakes it at goblin scale. The name also carries the Book of Cities flavor without putting any lore into the vanilla product.

Check before selling under it. A web search found a "Pixel Goblin Studio" (a small studio site and a SoundCloud) and a "Pixel Goblin" media site at pixelgoblin.link. It found no pixel-art tool with the name. That is not a trademark search. Run one (USPTO) before a commercial launch.

What got built

Everything below came out of the engine in this session, at the seeds shown in the build script. Flavor content (goblins, reef, glowcap) sits in flavors/boc/. Vanilla content makes CC0 sprites.

The workbench (published alongside this record) has six workshops: Generate (with brood, share codes and both verdicts), Edit (pencil, fill, line, box, shade and dither brushes, mirror, pixel-perfect strokes, frames, onion skin, sheet export), Convert (with Learn likeness), Tiles (paint a map, watch the autotiles), Backdrop (the layers scroll at their own speeds) and UI Kit. Readable and Swap sides are the first custom-layout slots.

SPIRE logic, ported

SPIRE's transfer map (its sub-skill i) says: port the ratchets first and almost everywhere, port two verdicts only where two questions exist, and don't port the hazard register's shape where nothing can hurt a body. I followed it, and found that two things in pixel art can hurt someone.

Bugs found along the way

In your stack

Vanilla Core, composite loading. QRen Coder and PixelGoblin both name their entry module vanilla_flavor. Python caches modules by name, so the second flavor loaded silently received the first one's code. Asked for block-types, QRen answered as PixelGoblin. patches/vanilla-core-composite-fix.patch fixes it (12 lines plus a regression test). All 40 Vanilla Core tests pass with it, and the new test fails without it. A flavor's helper modules can still collide if two flavors share names like utils; the full fix is per-flavor import isolation, noted for Vanilla Core's STANDARDS.md.

In PixelGoblin, caught by its own gates

  • 5 surviving mutants on the first falsification run. One was a test that could never see a shared stream. One was a 9-slice check blind to stripes. One was a leak-guard control that two patterns both caught. Two were mutations written wrong. All five were fixed in the checks, not exempted.
  • The L-corner definition was wrong: a staircase control had "zero" corners. It was rewritten to match how pixel-perfect strokes actually work.
  • The likeness ramp learned the outline as a skin colour, which gave black relatives. It now learns from interior pixels, weighted by coverage.
  • WFC 3×3 falls back at 48×48, which the gate never tested. It was measured, the default changed, and the limit is written down.
  • The first JavaScript ↔ Python parity run passed on every case. That is a result, not a bug, and gate B13 keeps it true.

Critique, round 2

What breaks this now

  1. Speed. Python is fine for tools and load-time generation, and too slow for per-frame crowds. Fix: cache by (type hash, seed); P1 Rust core.
  2. WFC at larger sizes with 3×3 patterns. Fix: backtracking, or grow in 24px chunks with edge constraints (P2).
  3. Parity covers the runtime only. The workbench's converter and UI-kit preview are separate JS code with no gate. Fix: move them behind the same parity gate, or label them preview-only (they are, today).
  4. extends replaces lists. The aquatic goblin lost its tunic because parts replaced the parent's. Fix: add a parts_add key that appends.
  5. The flash check is an approximation. Fix: it is labelled UNVERIFIED; run a certified tool (such as PEAT) before shipping public animations.
  6. Nobody but me has used it. SPIRE's own known limit applies: every fixture is synthetic. Fix: your first real Book of Cities catalog import will find what I couldn't.

Nearly free improvements

  • Name seeds: --seed-name Grubnak hashes a name to a seed, so an NPC's name is its look.
  • GIF export of idle animations (stdlib LZW, about 60 lines).
  • pixelgoblin watch for Dropzone: frog.png plus frog.tag in a folder converts on arrival.
  • Register the 16 SLM-e pieces into slme.db: one command, since the manifests already validate.
  • Squint: a readability check at 1x (silhouette contrast against a background).

What I want to add

Warren: dungeon rooms grown straight from the Book of Cities dungeon DAG, since "a dungeon is a sub-book" and a sub-book deserves its own tiles. CRUCIBLE ramps, so copper ore actually oxidises to verdigris in its palette. And a lineage view in the workbench, so a brood becomes a family tree you can click through.

What I think

The core bet held up. One small integer engine, many doors, and a determinism contract that now holds across two languages. That is rarer than it sounds, and it is the part no existing editor has. The workbench is useful but thin. That is the right order, not a flaw. The most valuable thing this session produced might not be PixelGoblin at all: it is the Vanilla Core fix, because every future composite run in your stack would have hit it.
